# Settings refinement

The existing Force settings page is the reference: retain its native type,
neutral surfaces, switches, fields and tag editing workflow. Use available
width for two related columns, and group application maintenance separately.

The header and page title stay visible at the same positions. Timing actions
continue to save as before; goal edits retain explicit Save/Undo. Editing a tag
focuses and reveals a compact form above the list. The form is hidden by default;
「新标签」 in the section header opens it. Name, classification and color use
aligned label rows inside a maximum 480-point width. Add/Save and Cancel sit
together immediately below the fields. Saving or cancelling collapses the form;
invalid input keeps the draft visible. Draft class/color changes preview in the
selected class button, while Save updates the list and Cancel restores saved values.
Switching edit targets retains the existing save/discard/cancel protection.
No action changes the current task, active timer or completed record snapshots.

At widths of 920 points and above, timing/application occupy a 280-point left
column and tags fill the remainder after a 32-point gap. Smaller windows stack
timing, tags, application. Update status stays next to its action and wraps;
folder access and quit have separate, aligned rows.

Check layout at 1040 × 780 and 780 × 620, including the 920-point breakpoint,
long labels, invalid input and scrolling. Native acceptance covers adding,
editing, cancelling, color preview and ordinary keyboard input after dialogs
and reopening the management window. A reopened tag draft restores input focus.
Headless layout checks do not establish native rendering or IME composition.
