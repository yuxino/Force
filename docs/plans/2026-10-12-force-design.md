# Force

用户要求：独立 macOS 刘海专注应用，使用 Wails，与 Nichijou 共用专注记录；项目名 Force，放在个人 GitHub 账号的私有仓库。

## 交互

- 收起：黑色小条贴在刘海下沿，显示任务标签和绝对时间计时；不占用刘海两侧菜单栏，没有刘海的屏幕采用菜单栏下方小条。
- 点击或短暂停留展开；单一黑色轮廓从刘海下沿连续变形，正文淡入。悬停打开后离开延迟收起，点击控件后保持；点击外部、Escape 或收起按钮关闭面板。展开后有正在进行的任务、今日目标、标签、新标签、历史与设置。
- 标签支持并行计时，与网页相同。点击正在计时的标签结束并保存；再次点击开始新记录。支持单项停止、停止全部。
- 今日目标 5 小时，只累计正向标签。负向用语义红色提示。默认不申请通知、辅助功能或屏幕录制权限。
- 支持每 15 秒同步、手动刷新、唤醒与展开刷新、长标签、滚动内容及屏幕配置变化。展开窗口从菜单栏下方开始，滚动区不显示滚动条。离线保留上次显示并禁止写入。

## 实现

Wails 2 的 Go 后端访问现有 Nichijou HTTPS API，React/TypeScript 渲染界面。小型 AppKit 桥负责刘海几何、窗口置顶、Spaces、菜单栏入口和无 Dock 图标。窗口使用固定透明画布，鼠标只在当前可见轮廓中接收事件。无需修改或部署 Nichijou。参考依据见 [刘海交互研究](../notch-interaction-research.md)。

默认专注记录归属使用网页 FocusWidget 的 FOCUS_OWNER_ID。配置不保存任何凭据。测试服务器只能通过启动参数指定，不写入用户配置。

## 计时规则来源

读取 Nichijou 当前源码 `src/components/widgets/FocusWidget.tsx`、`src/services/api.ts` 和 API 的 `src/controller/FocusController.ts`。

- 单项时间：`max(0, floor((now - startTime) / 1000))`。关闭应用与睡眠不自动停止服务器计时。
- 今日已完成：按本地日期匹配 startTime，再按标签种类汇总服务器 duration。
- 正向、负向、休闲：今日已完成加正在进行的同类任务。并行任务分别累计，与网页目标口径一致。
- 未知标签类别回退中性；归档标签仍参与历史类别判断。
- 当前网页的跨午夜口径：运行中计时保留整个会话累计；已完成记录归入开始日。Force 首版保持一致。
- 周统计直接使用服务器接口，其总实际时长合并重叠区间，标签投入时长分别累计。

## 验证

Go HTTP 测试覆盖读写 payload、日期查询、错误与既有会话兼容；计时回归覆盖多标签、归档、未来开始时间和跨日。实际 macOS 包验证签名、启动、刘海布局、收起展开、长名称和在线只读同步。写入集成使用测试服务器，避免为验收污染用户记录。
