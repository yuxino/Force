# Force

个人私有 macOS 专注应用，使用 Wails，与 Nichijou 共用专注记录。当前试用形态为悬浮计时条、展开专注面板和独立记录窗口。

## 交互

- 小计时条 280×54 点：时间、当前任务、额外并行任务数量、收进菜单栏。点击展开，不因悬停自动弹出。
- 展开面板 368×456 点：当前任务、今日目标、标签、新标签、设置。主要计时与目标固定，标签单独滚动。点击外部、Escape 或收起按钮关闭面板。
- 拖动小条左侧手柄或面板标题移动；位置保存到应用偏好，启动时恢复并限制在可见工作区。菜单栏可重置位置。
- 日历记录与本周统计使用独立的常规窗口，最小 600×480 点。关闭记录窗口保留计时条。
- 标签支持并行计时。点击正在计时的标签结束并保存；再次点击开始新记录。支持单项停止、停止全部。
- 今日目标 5 小时，只累计正向标签。负向使用语义红色提示。默认不申请通知、辅助功能或屏幕录制权限。
- 每 15 秒同步、手动刷新、唤醒与展开刷新。离线保留上次显示并禁止写入。未计时或负向计时过久时可展开提醒。

## 实现

Wails 2 的 Go 后端访问现有 Nichijou HTTPS API，React/TypeScript 渲染界面。`internal/desktop` 的 AppKit 桥负责浮动层级、窗口尺寸、手柄拖动、位置偏好、Spaces、菜单栏入口和无 Dock 图标。窗口跟随实际可见表面尺寸，不保留旧版大块透明画布。菜单栏使用系统 NSStatusItem 和原生菜单。

记录窗口复用 Wails 资源协议，通过独立只读消息桥读取状态、历史和周统计。验证来源与请求参数，并拒绝写入接口；主窗口继续使用 Wails 桥。无需修改或部署 Nichijou。

默认专注记录归属使用网页 FocusWidget 的 FOCUS_OWNER_ID。配置不保存任何凭据。测试服务器只能通过启动参数指定，不写入用户配置。

参考依据见 [悬浮形态研究](../floating-interaction-research.md)。早期刘海方案另行保留为历史研究。

## 计时规则来源

读取 Nichijou 当前源码 `src/components/widgets/FocusWidget.tsx`、`src/services/api.ts` 和 API 的 `src/controller/FocusController.ts`。

- 单项时间：`max(0, floor((now - startTime) / 1000))`。关闭应用与睡眠不自动停止服务器计时。
- 今日已完成：按本地日期匹配 startTime，再按标签种类汇总服务器 duration。
- 正向、负向、休闲：今日已完成加正在进行的同类任务。并行任务分别累计，与网页目标口径一致。
- 未知标签类别回退中性；归档标签仍参与历史类别判断。
- 当前网页的跨午夜口径：运行中计时保留整个会话累计；已完成记录归入开始日。Force 保持一致。
- 周统计直接使用服务器接口，其总实际时长合并重叠区间，标签投入时长分别累计。

## 验证

Go HTTP 测试覆盖读写 payload、日期查询、错误与既有会话兼容；记录桥测试拒绝写入和无效日期范围。计时回归覆盖多标签、归档、未来开始时间和跨日。实际 macOS 签名包验证尺寸、拖动、重启位置恢复、独立记录窗口与在线只读同步。写入集成使用合成测试服务器，不污染用户记录。具体证据与边界见 [验收记录](../verification.md)。
